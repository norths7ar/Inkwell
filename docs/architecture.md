# Inkwell（墨匣）架构设计与技术铁律

更新于 2026-11-26。本文记录 Inkwell（墨匣）的技术选型、核心分层与工程约束，均为从零搭建的终态架构决策。

## 1. 架构原则与跨项目对齐基线

### 核心原则

- **轻量、透明、可控**：控制流、协议细节、状态持久化与错误分类全部显式可见，避免黑盒框架掩盖底层语义。
- **最小依赖集**：优先使用 Python 标准库与轻量化基础组件，不引入与自身控制面重叠的重型编排或 ORM 框架。
- **单一事实源**：会话消息、挂起审批、待审变更与作品内容统一落入同一个业务 SQLite 数据库，杜绝双写状态漂移。

### 跨项目工程基线

与本机其他个人项目的工具链和底层协议保持一致，降低跨项目切换的记忆与维护成本：

- **Python 工具链**：Python `3.14.10` · `uv` `0.13.8` · Ruff `0.17.5` · Pyright `1.1.414`
- **前端工具链**：Node.js `26.13.1` · `pnpm` `12.21.0` · TypeScript + React · ESLint `10.15.0` · Prettier `3.10.1`
- **跨应用统一层**：统一采用自建 `httpx` 协议优先模型层、标准库 `sqlite3` 持久化，以及对接本机 Service Desk 的 `service/` 生命周期协议。

## 2. 模型接入层（`httpx` 协议优先）

彻底放弃按厂商封装的第三方 SDK（不引入 LangChain 及各家 `langchain-*` 扩展包），**以网络协议作为抽象的最小单位**。

- **协议驱动**：围绕核心线协议实现极薄驱动——`openai-chat`、`openai-responses`、`anthropic-messages`（按需扩展 `google-genai`）。共用挂载于应用生命周期的 `httpx.AsyncClient` 连接池，统一实现 SSE 解码与分层超时控制（连接超时与流式 chunk 空闲超时）。
- **统一内部表示（IR）**：消息内容显式建模为结构化块（`text`、`reasoning`、`tool_call`、`tool_result`、`image`），完整保留推理链（如 `reasoning_content` / `thinking` 块）以便工具续轮原生回传；输出统一的流式增量事件与模型用量事实。
- **结构化错误分类**：直接依据 HTTP 状态码、响应头（如重试等待窗口）与响应体映射出可重试、限流、认证、配额、上下文溢出等明确类别，不靠猜测多套 SDK 的文本异常。
- **声明式 Preset 与单模型覆盖**：厂商收敛为声明式配置（`base_url`、`default_protocol`、`discovery_url`、鉴权方式与少量兼容规则 `quirks`），同时保留**提供商默认协议 + 单模型级协议覆盖**，确保聚合平台上的新模型可独立指定路由协议。
- **独立零耦合边界**：模型接入包与小说业务域解耦，保持跨项目可复用。

## 3. 自研 Agent Loop 与统一工具契约

彻底放弃 LangGraph 与独立 Checkpointer，采用 **纯 Python `async` 控制流**：

- **显式主循环**：按“组装上下文（含作用域过滤与压缩覆盖层）→ 协议层流式推理 → 并发执行工具（带并发上限与取消传播）→ 追加结果并检查挂起或终止条件”组织，循环本身控制在清晰可读的数百行内。
- **单点事件流扇出**：循环内产出的领域事件（文本增量、思考增量、工具调用、工具结果、审批挂起、错误与重试重置）由单一分发点同时写入业务数据库与推送通道，从根本上消除“实时视图与库内历史不一致”的多状态机撕裂。
- **业务表原生挂起与恢复**：需要用户回答（`ask_user`）或工具审批时，直接把挂起请求与运行状态写入业务 SQLite；页面刷新或服务重启后，从业务表加载历史与挂起上下文即可确定性恢复执行。
- **中断与中途插话**：流式执行期间原生响应客户端取消信号（及时关闭上游 HTTP 流）与用户中途注入的新指令，不在图节点外另套并发状态。
- **统一工具契约**：
  - 所有工具遵循一致的输入校验、结构化返回与 `ToolFailure` 错误格式，校验失败返回精简可纠错提示而不回显整章正文。
  - **工具描述标准化**：工具描述仅说明三件事——适用场景、关键参数边界、副作用与返回值；一切工作流纪律（先读后写、确认边界等）统一收口到模式对应的 Markdown 系统提示词中。
- **后台辅助调用**：章节摘要、会话标题生成及可选的干净视角审稿，均直接发起独立、无编排负担的单次 LLM 调用，共享轻量后台模型配置与用量记录，不构建 Subagent 调度框架。

## 4. 数据存储层（单一 `sqlite3`）

彻底放弃 SQLAlchemy、SQLModel、Alembic、`aiosqlite`、LanceDB、FastEmbed 与 `aiocache`，所有本地持久化收敛为单一标准库 `sqlite3`：

- **连接与事务约定**：开启 WAL 模式、`foreign_keys=ON` 与合理的 `busy_timeout`；采用显式手写 SQL Repository 与 Pydantic / `dataclass` 领域模型，避免 ORM 会话状态隐式行为。
- **内置版本迁移**：利用 SQLite 原生 `PRAGMA user_version` 配合有序、可事务回滚的 Python 迁移脚本完成表结构演进。
- **全文检索（FTS5）**：章节、笔记与设定检索优先使用 SQLite 内置 FTS5 虚表（按需结合拼音或 trigram 分词支持中文精确与模糊查找）；在单部作品检索未被实证遇到瓶颈前，不引入向量库与本地模型依赖。

## 5. 前后端通信（REST + 原生 SSE）

彻底放弃 Socket.IO（无 `python-socketio` 与 `socket.io-client`），回归标准 HTTP 契约：

- **写操作与运行控制走 REST**：发送消息启动运行、审批/拒绝待审变更、回答挂起提问、中途取消、中途插话，以及所有书籍/章节/设定 CRUD 均通过标准 REST 接口完成。
- **实时流与状态通知走原生 SSE**：后端提供按递增序号 `seq` 编码的 SSE 事件流（`text_delta`、`reasoning_delta`、`tool_start`、`tool_result`、`approval_required`、`content_changed`、`run_done`、`run_error` 等），配合内存环形缓冲与 `Last-Event-ID` 断线重连补发。
- **TypeScript 友好契约**：前端仅需标准 `fetch` 与 `EventSource`，事件载荷对应明确的 TypeScript 联合类型（Discriminated Unions），网络层透明易测、无额外协议状态机。

## 6. 本机服务层契约（`service/`）

保留并复用统一的本机服务包装层，直接兼容本地 Service Desk 工具生态：

- 提供一致的生命周期命令（`start`、`stop`、`restart`、`status` 等）与运行记录管理。
- 暴露轻量的 `/health` 探针接口及规范化脱敏诊断输出，确保启动、状态检查与异常反馈行为与其他本地项目一致。

## 7. 前端架构与交互铁律

- **单一常驻外壳（Single AppShell）**：全站仅维护唯一一套四槽位常驻网格（`48px 一级导航轨 | 0↔200~420px 可调宽目录槽 | 内容槽 | 对话槽`）与**唯一一个 `<ChatPanel>` 实例**，各视图仅通过开关槽位宽度与模式参数切换（如进入作品时目录槽从本地记忆宽度展开，切至全屏「讨论」时收起内容槽并撑满对话槽）。严禁按页面复制多套外框或整棵卸载重挂导致流式生成与草稿状态丢失；内容槽内允许围绕同一工作区状态挂载轻量多文档 Tab 栏。
- **前端交互对齐 OpenFic**：对话渲染、过程/正文分离、思考强度（`reasoning_effort`）、悬浮回滚/Fork、`@` 引用、词级待审 Diff 与侧栏组织方式参照 OpenFic 前端体验，同时保持零冗余状态机的轻量 React + REST/SSE 实现。
- **对称控制与恒定导航**：`48px` 左轨全站一致（书架有作品时保留单书视图快捷入口，绑定最近打开的作品），不放折叠开关；左右面板折叠/展开按钮唯一且对称置于中间主画布顶栏左/右两端（全屏讨论与待审页亦置于主画布最左），避免重复控件或切换页面后按键跳位。
- **信息与动作分离、拒绝表单堆积**：编辑器顶栏左侧仅展示只读元信息与保存状态，右侧仅放置纯图标动作；禁止在窄侧栏、AI 面板顶部或窄设置栏堆砌横向 Tab 与大段解释废话；设置面板采用放大弹窗 + Master-Detail 分栏组织，把日常高频改动（名称、可见性、所属文件夹/分组）留在目录列表外层直操。

## 8. 独立发布预留约束（Docker / 桌面壳）

现阶段不引入具体打包配置，但从首次编码起遵守以下四条零成本护栏，确保未来可平滑接入 Docker 单容器、Electron、Tauri（sidecar）或 `pywebview`：

- **单一可配置数据目录（`INKWELL_DATA_DIR`）**：SQLite 数据库、快照备份、附件与运行日志全部收口到可配置目录（环境变量或 `--data-dir`），不写死源码目录或当前工作目录。
- **前端纯静态产物 + 同源相对路径**：前端 REST 与 SSE 请求一律使用相对路径 `/api/...`，发布态由 FastAPI 直接托管静态产物目录 `dist/`，兼容单容器部署与桌面壳指向本地端口。
- **运行参数化与平台隔离**：`host`、`port`（支持显式或随机端口）与优雅退出（关闭 `httpx` 连接池和 SQLite WAL）全部参数化；操作系统专属的进程/服务管理逻辑严格隔离在 `service/`，核心 `app/` 保持纯跨平台 Python（使用 `pathlib.Path`）。
- **可插拔凭据加密边界**：将密钥加解密抽象为极薄接口（`encrypt` / `decrypt`），本机可使用系统凭据保护，Linux 容器等环境可无缝切换为密钥文件或环境变量，不将单一平台 API 写死在业务层。
