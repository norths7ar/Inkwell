# Inkwell（墨匣）产品设计与边界

更新于 2026-11-23。本文记录 Inkwell（墨匣）从零启动时已拍板的产品边界、功能划分与非目标；OpenFic 仅作为功能参照与踩坑来源，不作为代码上游。

## 1. 产品定位与核心原则

Inkwell 面向单机个人长短篇小说创作，强调可控、透明、低噪音的创作体验，遵守四条核心原则：

- **作者掌握最终决策**：AI 协助讨论、起草、改写与核查，但正文与核心设定的正式落库由作者审阅或明确授权。
- **作品内容层与元层面清晰分离**：日常写作界面只承载作品本身与创作流；模型、模式提示词、写作规则与服务管理统一收敛到左下角的元层面入口，不干扰写作视线。
- **模式代替复杂编排**：以少而清晰的创作模式约束行为与工具边界，拒绝把通用编程 Agent（Coding Harness）的重型概念硬搬进小说创作。
- **先精简、按实证演进**：所有已确认的日常写作刚需均在规划范围内；在简单方案被实证不足之前，不提前引入重型基础设施。

## 2. 作品内容层（核心保留能力）

保留并精炼日常小说创作必需的工作区能力，按以下模块组织：

| 模块 | 职责与核心能力 |
| --- | --- |
| 书 / 卷 / 章工作区 | 书籍管理、分卷与章节组织、正文编辑器，以及章节/设定的修订历史与版本回溯 |
| 设定与资料体系 | 人物卡片、世界观条目、自由笔记与章节摘要，服务于长篇连贯性维护 |
| 知识可见性边界 | 局部/全局上下文范围控制，隔离跨书资料与当前章节/角色不应知晓的剧透信息，防止串戏与角色超知 |
| 讨论 / 写作 / 审阅工作流 | 面向剧情讨论、正文起草改写、连贯性核查的连贯对话与上下文组装 |
| 待审变更（Pending Changes） | AI 对正文或正式设定的修改以结构化 Diff 呈现在待审区，支持逐项审阅、应用或拒绝 |
| 上下文管理与数据流转 | 长会话上下文压缩、项目包导入导出，以及本地快照与数据备份 |

## 3. 元层面设计（左下角）

软件配置与控制面统一置于左下角“元层面”入口，收敛为四个完全正交、职责不重叠的板块：

### 3.1 模型与提供商（Providers & Models）

- 管理各 API 连接地址、鉴权凭据与可见模型目录。
- 保留**提供商默认协议 + 单模型级协议覆盖**，兼容多协议聚合平台与新上线模型。
- 区分默认主写作模型与后台轻量模型（用于章节摘要、会话标题等独立低成本调用）。

### 3.2 写作模式与系统提示词（Modes & Prompts）

- 仅内置 **2~3 个清晰模式**：
  - **讨论（Discuss）**：只读作品资料，可针对设定与笔记提出待审建议，不直接修改章节正文。
  - **写作（Write）**：读写章节正文与设定资料，默认通过待审变更流转，或按设置直接落盘。
  - **审阅（Review，可选）**：只读作品资料，聚焦时间线、人物动机、因果链与知识边界核查。
- **工具权限直接绑定模式**，取消独立的逐工具权限矩阵与多角色子 Agent 委派配置。
- 每个模式仅对应**一份直白、可编辑的 Markdown 系统提示词**，支持一键恢复默认；取消多段拼接、版本树与宏编译器。

### 3.3 写作规则与个人片段（Rules & Snippets）

- **写作规则（Rules）**：分为全局规则与单书规则两层，使用纯 Markdown 编写个人文风偏好与硬约束，自动注入对应作用域的上下文。
- **个人片段（Snippets）**：可选的用户自建扁平 Markdown 模板（如个人审稿清单、分场提纲格式），在输入框通过 `@` 或 `/` 手动显式引入当前轮次。
- **零内置套路模板**：不预置网文流派模板、投稿范式或方法论长文，避免污染作者自身文风。

### 3.4 本机服务与数据（Service & Data）

- 展示本机后端服务状态、端口与日志入口。
- 提供手动备份、快照恢复与项目包导入导出。

## 4. 明确不做（Non-Goals）

为防止架构再次膨胀，以下能力明确排除在项目设计之外：

- **多角色 Subagent 委派与编排体系**：小说写作高度依赖连续语境与潜台词，拆给隔离上下文的子 Agent 极易失真；章节摘要或干净视角审稿仅作为独立单次 LLM 调用处理。
- **多层 Skills 体系与工程化 PromptChain**：取消内置技能包、嵌套参考文档、分段组装的 PromptChain、宏编译器及独立命令体系。
- **向量数据库与本地嵌入索引**：在 `sqlite3` FTS5 全文检索被实证无法满足需要之前，不引入向量库与本地 ONNX 嵌入模型。
- **非个人本地创作能力**：多租户与远程登录鉴权、远程穿透隧道、移动端打包、本地语音转写、重型全格式办公文档解析库，以及第三方分析遥测。

## 5. 后续启动前待细化事项

正式进入编码前，仅需围绕首期落地补充以下交互与契约细节：

- **模式与待审边界细化**：确认审阅能力是独立模式还是讨论模式下的专项提示片段，以及“待审变更 / 直接写入”的默认开关位置。
- **核心表与字段定义**：拍板书/卷/章、设定/笔记、修订历史、待审变更与会话消息的最小 SQLite 表结构。
- **编辑器与界面布局**：确定正文编辑器选型及工作区三栏布局的交互细节。
