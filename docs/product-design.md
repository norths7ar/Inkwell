# Inkwell（墨匣）产品设计与边界

更新于 2026-11-26。本文记录 Inkwell（墨匣）的核心产品边界、功能划分、交互原则与非目标；OpenFic 的前端体验与交互打磨作为直接对齐参照（不引入其多智能体后台编排复杂度）。

## 1. 产品定位与核心原则

Inkwell 面向单机个人长短篇小说创作，强调可控、透明、低噪音的创作体验，遵守四条核心原则：

- **作者掌握最终决策**：AI 协助讨论、起草、改写与核查，但正文与核心设定的正式落库由作者审阅或明确授权。
- **作品内容层与元层面清晰分离**：日常写作界面只承载作品本身与创作流；模型、模式提示词、写作规则与服务管理统一收敛到左下角的元层面入口，不干扰写作视线。
- **模式代替复杂编排**：以少而清晰的创作模式约束行为与工具边界，拒绝把通用编程 Agent（Coding Harness）的重型概念硬搬进小说创作。
- **先精简、按实证演进**：所有已确认的日常写作刚需均在规划范围内；在简单方案被实证不足之前，不提前引入重型基础设施。

## 2. 作品内容层（核心保留能力）

保留并精炼日常小说创作必需的工作区能力，按以下模块组织：

| 模块 | 职责与核心能力 |
| --- | --- |
| 书 / 卷 / 章工作区 | 书籍与封面管理、分卷与章节组织、支持 `200px ~ 420px` 右边缘拖动调宽的目录侧栏、工作区轻量多文档 Tab 栏、纯 Markdown 编辑器，以及章节/设定的修订历史与版本回溯（章节摘要维护暂缓，按需再启用） |
| 设定与资料体系 | 统一「设定」入口（内部分组为人物、世界、笔记），支持**仅一层文件夹（`category`）聚合**、侧栏快速筛选、列表行左侧抓手拖拽排序/跨组调整、`移动到…` 级联菜单，以及明确入口的批量管理（批量修改可见性、批量移动、批量删除） |
| 知识可见性边界 | **防剧透与私密隔离**：设定条目在目录列表行内直接一键切换 `公开 ↔ 仅全局`，无需进入二级弹窗；AI 会话默认 `仅公开资料`（不读取隐藏设定），底部 `仅公开` 胶囊一键直接升级为 `全局 🔒`（无需二次弹窗确认），且**同会话单向不可逆**（历史上下文已包含隐藏内容时禁止退回） |
| 讨论 / 写作 / 审阅工作流 | 空白直聊免起名开场（由后台轻量模型异步生成标题，`SquarePen` 图标开启新对话）；单轮思考块与工具调用合并折叠（浅灰竖线时间轴、显示思考耗时，无思考/工具时不展示）；Markdown 正文渲染与消息悬浮操作（复制、回滚、Fork 分支）；双行顶栏实时展示 Token 用量与上下文占比；模型旁提供思考强度（`reasoning_effort`）切换、输入框未发草稿暂存与 `@` 引用章节/设定；对话侧栏支持两行信息卡片（标题 + 相对时间/模式）、顶部 `SquarePen` + `...`（排序 / 清空）及单项置顶、重命名、删除 |
| 待审变更（Pending Changes） | AI 对正文或正式设定的修改以**词/句级行内高亮 Diff** 呈现在待审区，支持逐项或一键批量应用/拒绝 |
| 上下文管理与数据流转 | 后端驱动的长会话上下文压缩（Compaction：摘要早期对话并保留最近轮次）、本地 SQLite 快照备份，以及简洁的后端双向导入导出（按卷/章/设定分目录 ZIP 与可选单文件 TXT/Markdown 合集，不做浏览器伴随备份包） |

## 3. 元层面设计（左下角）

软件配置与控制面统一置于左下角“元层面”入口，收敛为四个完全正交、职责不重叠的板块：

### 3.1 模型与提供商（Providers & Models）

- 管理各 API 连接地址、鉴权凭据与可见模型目录。
- 保留**提供商默认协议 + 单模型级协议覆盖**，兼容多协议聚合平台与新上线模型。
- 区分默认主写作模型与后台轻量模型（用于章节摘要、会话标题等独立低成本调用）。

### 3.2 写作模式与系统提示词（Modes & Prompts）

- 仅内置 **2~3 个清晰模式**：
  - **讨论（Discuss）**：只读作品资料，可针对设定与笔记提出待审建议，不直接修改章节正文。
  - **写作（Write）**：读写章节正文与设定资料，默认通过待审变更流转，或按设置直接落盘。
  - **审阅（Review，可选）**：只读作品资料，聚焦时间线、人物动机、因果链与知识边界核查。
- **工具权限直接绑定模式**，取消独立的逐工具权限矩阵与多角色子 Agent 委派配置。
- 每个模式仅对应**一份直白、可编辑的 Markdown 系统提示词**，支持一键恢复默认；取消多段拼接、版本树与宏编译器。

### 3.3 写作规则与个人片段（Rules & Snippets）

- **写作规则（Rules）**：分为全局规则与单书规则两层，统一收口在设置面板的「写作规则」板块（工作区侧栏不设独立入口）；使用纯 Markdown 编写个人文风偏好与硬约束，自动注入对应作用域的系统上下文（模式提示词 → 全局规则 → 当前作品信息与单书规则）。
- **个人片段（Snippets）**：可选的用户自建扁平 Markdown 模板（如个人审稿清单、分场提纲格式），在输入框通过 `@` 或 `/` 手动显式引入当前轮次（M2）。
- **零内置套路模板**：不预置网文流派模板、投稿范式或方法论长文，避免污染作者自身文风。

### 3.4 本机服务与数据（Service & Data）

- 展示本机后端服务状态、端口与日志入口。
- 提供手动备份、快照恢复与项目包导入导出。

## 4. 明确不做（Non-Goals）

为防止架构再次膨胀，以下能力明确排除在项目设计之外：

- **多角色 Subagent 委派与编排体系**：小说写作高度依赖连续语境与潜台词，拆给隔离上下文的子 Agent 极易失真；章节摘要或干净视角审稿仅作为独立单次 LLM 调用处理。
- **多层 Skills 体系与工程化 PromptChain**：取消内置技能包、嵌套参考文档、分段组装的 PromptChain、宏编译器及独立命令体系。
- **向量数据库与本地嵌入索引**：在 `sqlite3` FTS5 全文检索被实证无法满足需要之前，不引入向量库与本地 ONNX 嵌入模型。
- **非个人本地创作能力**：多租户与远程登录鉴权、远程穿透隧道、移动端打包、本地语音转写、重型全格式办公文档解析库，以及第三方分析遥测。

## 5. 当前已拍板的产品交互细则

- **编辑器边界**：正文与设定坚持纯文本 / Markdown 编辑器，以显式保存与 `Ctrl+S` 为主，辅以 `localStorage` 停笔防抖草稿与脏状态切换保护；保留无边框纸面观感，不在工具栏堆砌富文本控件。
- **模式与待审流转**：`讨论`（只读正文、可提设定待审建议与 `ask_user`）、`写作`（可提正文/设定待审建议，必须经待审区逐项应用或拒绝后才正式落库）与 `审阅`（全只读核查）三模式；模式提示词页内附只读可用工具边界提示，不提供逐工具权限矩阵。
- **列表外层直操**：高频操作优先在列表外层完成（行内可见性直切、拖拽排序与跨组/跨文件夹拖动、`移动到…` 子菜单；对话项置顶、重命名、删除），避免把低频/常规属性全部塞进大型二级属性表单。
- **前端体验对标 OpenFic**：对话区交互（过程/回答分离与浅灰竖线时间轴、思考强度 `reasoning_effort`、思考耗时、悬浮复制/回滚/Fork、草稿暂存、`@` 引用）、目录侧栏拖动调宽与轻量多 Tab 文档切换，以及待审词级行内 Diff 均以 OpenFic 前端为体验基线落地。
